# CipherCraft messenger backend

Run locally from the repository root with `python scripts/run_messenger.py` (127.0.0.1:8503). The app uses only the Python standard library. Python 3.10+ is required. Tests: `python -m unittest discover -s tests -p test_messenger.py -v`.

`password` is the client's domain-separated PBKDF2-derived authentication secret, **not the user's raw password**. A 43-character base64url auth secret is accepted. The server applies PBKDF2-HMAC-SHA256 with 600,000 iterations and an independent random 16-byte salt. Clients must use a separately derived encryption key and random salt for keyBackup. The server never encrypts or decrypts messages or backups. Public keys are immutable and validated as finite P-256 curve points. Registration rejects additional public-key fields (including private d).

## Configuration and production

- `CIPHER_MESSENGER_DB`: durable SQLite file. Default locally is ignored `.venv/messenger.sqlite3`; on Azure (WEBSITE_SITE_NAME set), `/home/data/cipher-messenger.sqlite3`. Provision a persistent writable directory; ephemeral container storage loses accounts. The app uses journal_mode=DELETE for the single-worker beta, avoiding WAL shared-memory requirements on Azure /home shared storage. Azure filesystem locking and persistence still require hosted verification. Back up SQLite consistently with its backup API; do not copy a live database alone. Restrict filesystem access to the service account.
- `CIPHER_MESSENGER_ORIGINS`: comma-separated exact origins. Default `http://localhost:8502,https://cipher.drewclark.io,https://localhost`. No wildcard, credentials, path or trailing slash. Empty configuration disables cross-origin browser access. Origin-less server clients are allowed. No cookies or credentialed CORS. Bearer tokens belong only in Authorization, never URLs.
- TLS termination is required in production. Forward traffic from the HTTPS reverse proxy to gunicorn on a private interface/network. By default rate limits use REMOTE_ADDR. Set `CIPHER_MESSENGER_TRUST_PROXY=1` only behind a trusted front proxy that appends the actual client IP as the rightmost X-Forwarded-For value. In that mode only that rightmost valid IP is used; malformed/missing values fall back to REMOTE_ADDR. With the variable unset or any value other than 1, forwarded headers are ignored. A proxy may otherwise cause all clients to share its IP quota. Never expose trusted-proxy mode directly to untrusted clients.
- Install `messenger-requirements.txt` and run `gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 4 --timeout 60 --access-logfile /dev/null src.messenger.wsgi:application`. The generated startup script honors PORT. Keep a single worker for this small prototype. Disable proxy/body/header diagnostic logging and query logging. Do not enable gunicorn request access logs containing credentials. The local runner suppresses request logs.
- `python scripts/package_messenger.py` generates `dist/messenger-api.zip` using a fixed allowlist: backend Python files, this document, local runner, dependency files and a generated startup.sh. No existing frontend/startup/deployment files, credentials, databases or local plans are included. The ZIP can be inspected before separately authorized deployment to the user-authorized existing F1 Python 3.12 App Service as an API-only replacement after local verification; the separately hosted static main frontend is unaffected. No deployment or existing App Service changes are performed by these scripts. Remove the generated ZIP before committing source.

## Exact success response shapes

All IDs are positive JSON integers. createdAt and updatedAt are Unix UTC seconds. All success responses use HTTP 200 and JSON; errors use `{ "error": "code" }` and an appropriate 4xx/5xx status. POSTs require a JSON object and Content-Length, including `{}` for logout. A request body is limited to 65,536 bytes. Unpadded canonical base64url is required for cryptographic fields.

- `GET /api/health` -> `{ "ok": true }`.
- `POST /api/register {username,password,publicKey:{kty:"EC",crv:"P-256",x,y},keyBackup:{salt,iv,ct}}` -> `{ "token": string, "user": { "id": integer, "username": string, "publicKey": {"kty":"EC","crv":"P-256","x":string,"y":string}, "keyBackup": {"salt":string,"iv":string,"ct":string} } }`.
- `POST /api/login {username,password}` -> same registration response.
- `GET /api/me` -> `{ "user": {id,username,publicKey,keyBackup} }`.
- `POST /api/logout {}` -> `{ "ok": true }` (revokes only current token).
- `GET /api/people?username=exact` -> `{ "user": {id,username,publicKey} }`; no directory endpoint, unknown name returns 404.
- `GET /api/conversations` -> `{ "conversations": [{"id":integer,"peer":{id,username,publicKey},"updatedAt":integer,"unread":integer,"blocked":boolean}] }` ordered newest first.
- `POST /api/conversations {username}` -> `{ "conversation": {id,peer,updatedAt,unread,blocked} }`; existing pair returns existing conversation, self-pairs rejected.
- `GET /api/conversations/ID/messages?after=ID` -> `{ "messages": [{"id":integer,"senderId":integer,"envelope":{"v":1,"iv":string,"ct":string},"createdAt":integer}], "hasMore": boolean }`. Omitted after means 0; ascending IDs, at most 50 messages. Continue with last returned ID; GET does not mark read.
- `POST /api/conversations/ID/messages {clientId:randomUUIDv4,envelope:{v:1,iv,ct}}` -> `{ "message": {id,senderId,envelope,createdAt} }`. A retry with the same sender/clientId, conversation and envelope returns the original message. Reuse with different content or conversation returns 409. Concurrent retries serialize. Blocked conversations reject sends, including retries, with 403.
- `POST /api/conversations/ID/read {messageId:integer}` -> `{ "ok": true }`. Advances monotonically to the highest existing message in this conversation at or below messageId. Future sends remain unread even if a caller supplies an enormous marker. unread counts incoming messages only.
- `POST /api/conversations/ID/block {blocked:boolean}` -> `{ "conversation": {id,peer,updatedAt,unread,blocked} }`. blocked reflects the caller's block, not the peer's setting. Either member's block prevents sends in both directions; either may read history. Only the blocker can remove their own block.
- `OPTIONS` on API requests requires a listed Origin and Access-Control-Request-Method GET/POST, with requested headers limited to Authorization/Content-Type; returns `{ "ok": true }` with validated CORS headers.

Every endpoint except health/register/login/preflight requires `Authorization: Bearer TOKEN`. Tokens contain 32 random bytes, only SHA-256 hashes are stored, and expire after seven days. Unauthorized conversation IDs are indistinguishable from missing IDs (404). Username syntax is 3–24 lowercase ASCII letters/digits/underscore. Authentication secret length is 12–1024 characters. Backup salt is 16 bytes, IV is 12, ciphertext is 16–4096 bytes; message IV is 12, ciphertext is 16–30,720 bytes (including GCM tag). Ciphertext structure/authenticity and correct client key derivation cannot be verified by this server.

## Prototype limits

Fixed-window durable SQLite rate limits: auth 30/IP and 10/account per 15 minutes (register/login combined), send 120/account and 240/IP per minute; lookup 60/account/minute, conversation creation 30/account/minute. Counters persist across restarts, expired rows are pruned, and the table is capped at 10,000 entries. Very high churn can evict active counters; enforce additional proxy limits for public high-volume operation. A 429 includes conservative Retry-After: 900. Account limits can be used to temporarily deny another user's login. No secrets or raw IPs/account names are stored in rate counter keys (hashed identifiers are still linkable).

No password reset, account/key rotation, device-management UI, user-facing session list, WebSocket delivery, encrypted attachments or distributed scaling is provided. Push, administration and self-service deletion are documented in docs/ANDROID_NOTIFICATIONS.md, docs/ACCOUNT_ADMINISTRATION.md and docs/ACCOUNT_DELETION.md. Conversation listing is not paginated. Message history and sessions can grow with usage (expired sessions prune on limited operations). Protect storage and monitor capacity externally. Metadata (accounts, public keys, conversation membership, timing, size and block state) is visible to the server; this is not an audited end-to-end encryption protocol. Clients must authenticate keys and implement nonce discipline and ciphertext validation. Hard global limits of 500 accounts and 20,000 messages reject new records with HTTP 429 (`user_capacity_reached` / `message_capacity_reached`); message retries still work at capacity. Caps and inserts are serialized. Message ciphertext alone can occupy about 820 MB at the cap because base64url adds overhead; monitor free-plan disk usage. Hosted Azure beta deployment, persistence and TLS have been checked; production load and availability guarantees have not been established.
